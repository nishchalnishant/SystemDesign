### About the authors

**Kathy Sierra** has been interested in learning theory since her days as a game designer (she wrote games for Virgin, MGM, and Amblin'). She developed much of the Head First format while teaching New Media Authoring for UCLA Extension's Entertainment Studies program. She has been a master trainer for Sun Microsystems, teaching Sun's Java instructors how to teach the latest Java technologies, and a lead developer of several of Sun's Java programmer and developer certification exams. She is the founder of javaranch.com and the Creating Passionate Users blog. Along with this book, she co-authored *Head First Servlets*, *Head First EJB*, and *Head First Design Patterns*.

**Bert Bates** is a software developer and architect; a decade-long stint in artificial intelligence drove his interest in learning theory and technology-based training. He has taught programming to clients for years and has been a member of the development team for several of Sun's Java Certification exams. He spent the first decade of his software career traveling the world helping broadcast clients (Radio New Zealand, the Weather Channel, A&E), including building a rail system simulation for Union Pacific Railroad. He co-authored the same books as Kathy.

Dedication: *"To our brains, for always being there (despite shaky evidence)."*

### What the book covers

Head First Java is a hands-on introduction to the Java programming language and object-oriented programming, covering: Java syntax and program structure, objects and classes, variables (primitives vs. references), object behavior and state, methods and flow control, the Java standard library (API), inheritance and polymorphism, abstract classes and interfaces, object lifecycle and garbage collection, numbers/formatting/wrapper classes/statics, exception handling, GUI programming (Swing, event handling, inner classes), object serialization and I/O, networking (sockets) and multithreading, collections and generics, packaging/deployment (JARs, Java Web Start), and distributed computing (RMI, with a look at Servlets, EJB, and Jini).

### Pedagogical philosophy — "Head First" learning theory

The book explicitly rejects the reference-manual approach: *"This is NOT a reference book. Head First Java is a book designed for learning, not an encyclopedia of Java facts."*

**Who this book is for** — answer "yes" to all three:
1. Have you done some programming?
2. Do you want to learn Java?
3. Do you prefer stimulating dinner party conversation to dry, dull, technical lectures?

**Who should back away from this book** — answer "yes" to any:
1. Is your programming background limited to HTML only, with no scripting language experience? (Looping or if/then logic experience is fine; HTML tagging alone might not be enough.)
2. Are you a kick-butt C++ programmer looking for a reference book?
3. Are you afraid to try something different?

**The brain science premise ("Your brain on Java"):** The intro frames the core problem as the brain's own design — it is tuned to discard routine, ordinary content and only retain what feels urgent or novel (like danger from a tiger), so a technical book must trick the brain into treating the material as important.

**Learning principles the authors applied ("Some of the Head First learning principles"):**
- **Make it visual.** Images are far more memorable than words alone; combining text and pictures (with words embedded within or near the graphics they describe, not in a caption or body text elsewhere) improves recall and transfer by up to 89% and can make learners up to twice as likely to solve related problems.
- **Use a conversational and personalized style.** First-person, direct-to-the-reader, story-telling language outperformed formal tone by up to 40% on post-learning tests in recent studies.
- **Get the learner to think more deeply.** Passive reading does little; readers need challenges, exercises, and thought-provoking questions that engage both sides of the brain and multiple senses.
- **Get — and keep — the reader's attention.** Novelty, surprise, and the unexpected accelerate learning of even tough, technical topics.
- **Touch their emotions.** Memory strength is tied to emotional content — surprise, curiosity, fun, "what the...?", and the feeling of "I Rule!" when solving a puzzle.

**What the authors actually did to apply these principles** (from "Here's what WE did"): used pictures with embedded text; used repetition across different media and senses; used concepts and pictures in unexpected/novel ways; used emotional content (humor, surprise, interest); used a personalized conversational style; included more than 50 exercises, made challenging-yet-doable; used multiple learning styles (step-by-step, big-picture, code-first); addressed both sides of the brain; included stories/exercises with more than one point of view to force evaluation and judgment; included open-ended challenges without a single straight answer; and used an "80/20 approach" — covering only what you'll actually use, not everything, on the assumption this won't be your only Java book.

**"Metacognition: thinking about thinking"** — the intro urges readers to pay attention to how they pay attention, and to take responsibility for tricking their own brain into treating Java as Really Important, since most people are never taught how to learn, only expected to.

**"Here's what YOU can do to bend your brain into submission"** — the 10 numbered tips (printed as a cut-out-and-stick-on-your-refrigerator list):

1. **Slow down.** The more you understand, the less you have to memorize. Don't just read — stop and think. When the book asks a question, don't skip to the answer.
2. **Do the exercises. Write your own notes.** Doing them for you would be like someone else doing your workouts. Use a pencil — physical activity while learning can increase learning.
3. **Read the "There are No Dumb Questions."** All of them — they're not optional side-bars, they're part of the core content.
4. **Don't do all your reading in one place.** Stand up, stretch, move around, change chairs/rooms — helps your brain feel something and keeps learning from being too tied to one place.
5. **Make this the last thing you read before bed.** Or at least the last challenging thing — part of learning (especially transfer to long-term memory) happens after you put the book down, and new input during that processing time can cause loss of what you just learned.
6. **Drink water. Lots of it.** The brain works best hydrated; dehydration (which can occur before you feel thirsty) decreases cognitive function.
7. **Talk about it. Out loud.** Speaking activates a different part of the brain; explaining something out loud to someone else surfaces ideas you hadn't noticed while reading.
8. **Listen to your brain.** Watch for overload (skimming, forgetting what you just read) and take a break — cramming past that point doesn't help and can hurt.
9. **Feel something!** Get involved with the stories, make up your own captions for the photos — even groaning at a bad joke beats feeling nothing.
10. **Type and run the code.** Then experiment with changing or breaking it. Source for long examples and Ready-Bake code is downloadable from wickedlysmart.com.

## How to Use This Book

### We use simple UML-like diagrams

If pure UML had been used, readers would be seeing something that looks like Java but with syntax that's just plain wrong. So the book uses a simplified, modified version of UML that doesn't conflict with Java syntax — useful for readers who don't already know UML, since they won't have to learn Java and UML at the same time.

### Organizing and packaging code is deferred

The book doesn't worry about organizing and packaging your own code until the end (Chapter 17), so readers can focus on learning Java itself without stressing over organizational/administrative details early on. These details matter in the real world and are covered in depth, just saved for later.

### Exercises vs. puzzles

- **End-of-chapter exercises are mandatory**; **puzzles are optional**. Answers for both are at the end of each chapter.
- Puzzles are logic puzzles, brain teasers, crossword puzzles, etc. — meant for puzzlers, and it's fine not to solve them.
- **"Sharpen Your Pencil"** exercises do not have printed answers — for some there's no single right answer, and deciding whether your answer is right is part of the learning experience. Some suggested answers are available on wickedlysmart.com.

### Code examples are lean

Most examples are shown within the smallest possible context so the part being taught is clear and simple. The code is not meant to be robust or complete — that's the reader's job after finishing the book. Examples are written specifically for learning and aren't always fully functional.

### What you need for this book

- No IDE required or recommended — a basic text editor is strongly recommended until you complete the book (especially before Chapter 16), since an IDE can hide details that matter.
- **Setting up Java:**
  - A Java 2 Standard Edition SDK, version 1.5 or greater, is required (free from java.sun.com for Linux, Windows, Solaris). Mac OS X 10.4 already includes it.
  - The book is based on Java 1.5 (a.k.a. Java 5, a.k.a. "Tiger" — Sun renamed 1.5 to "Java 5" shortly before release while keeping "1.5" as the SDK version number; there was never a Java 3.0 or 4.0).
  - The SDK does not include API documentation — download the J2SE API docs separately from java.sun.com.
  - Any text editor works (vi, emacs, pico, Notepad, Wordpad, TextEdit, etc.) as long as it doesn't append ".txt" to source files.
  - Add the SDK's `/bin` directory to your PATH so the terminal can find `javac`.
  - If using Java 6: the book still applies, since Java 6 only added minor API additions relative to Java 5.
  - Installation trouble: join the Java-Beginning forum at javaranch.com.
- Much of the book's code is available for download at wickedlysmart.com.

### Last-minute things you need to know

This is a learning experience, not a reference book — content that might get in the way of learning the current topic was deliberately stripped out. The first read-through should start at the beginning, since the book builds on earlier assumptions about what you've already seen.
